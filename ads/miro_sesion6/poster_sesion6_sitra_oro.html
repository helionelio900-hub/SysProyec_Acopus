1. ¿Qué es ACL? (Anti-Corruption Layer)
BomERP maneja su propia estructura de negocio para guardar liquidaciones y pesajes de oro, pero SUNAT exige un estándar tributario estricto: UBL 2.1 XML.
¿Cómo solucionamos esto? Con una capa anticorrupción que traduce y aísla ambos mundos.

2. Circuit Breaker Pattern
Protege a SITRA-ORO contra caídas de servicios externos (API DNI RENIEC o API Cotización Spot). Evita hilos colgados y fallos en cascada cortando llamadas temporalmente.
Estado ¿Qué significa?
CLOSED Todo funciona normalmente. Solicitudes fluyen.
OPEN Fallas reiteradas. Se cortan peticiones y se responde con caché.
HALF_OPEN Pruebas de sondeo para comprobar si el servicio ya revivió.
Resiliencia: Si cae el proveedor Spot, el sistema entrega la última cotización guardada en Redis en menos de 5 ms.
3. ¿Qué son los Domain Events?
Imagina que SITRA-ORO registra una venta de oro. El módulo de ventas anuncia por un altavoz: «¡Se acaba de registrar una venta!».
  • Inventario / Bóveda: Actualiza las existencias de oro.
  • Reportes y Trazabilidad: Registra la operación.
  • Inteligencia Artificial: Analiza las tendencias de precio.
El módulo emisor no necesita conocer quién escucha el anuncio.
Domain Event: Un aviso que comunica que ocurrió un hecho trascendente en el sistema.
4. ¿Qué es Saga?
BomERP liquida compras de oro y las envía a SUNAT en varios pasos coordinados:
  1. Reúne las boletas / liquidaciones del día.
  2. Envía el resumen a SUNAT y recibe número de ticket.
  3. Consulta estado del ticket y SUNAT responde aceptación o rechazo.
¿Y si SUNAT rechaza? BomERP ejecuta transacciones compensatorias para anular la liquidación y liberar el oro. Para coordinar esto se usa Saga.
