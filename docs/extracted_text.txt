1. Resumen Ejecutivo y Cumplimiento de la Sesión S11
El presente informe consolida la implementación completa, reproducible y verificada de la seguridad frontend en la arquitectura Single Page Application (SPA) desarrollada con Angular 19 Standalone para el sistema empresarial SITRA-ORO. Siguiendo con exactitud el sílabo oficial de Lenguaje de Programación II (Unidad 2, Sesión 5), se ha articulado el cliente web con el Authorization Server externo Keycloak 26 (puerto 38081, Realm Sitra_oro) y el backend REST empresarial Spring Boot 3 Resource Server (puerto 8081).
Autenticación OIDC/OAuth2 Direct Access Grants: El formulario de acceso (/ingresar) interactúa con el endpoint de token de Keycloak emitiendo credenciales asimétricas RS256 con vigencia de 300 segundos.
Gestión Reactiva del Estado con Angular Signals: SesionService gestiona de forma inmutable el estado de la sesión (tokenActual, rol, documento, nombreUsuario, autenticado) consumiendo los roles desde realm_access.roles.
Persistencia Segura en sessionStorage: El Access Token se resguarda bajo la clave sitraoro.accessToken, garantizando persistencia ante recargas (F5) pero aislamiento absoluto entre pestañas/ventanas del navegador.
Control de Expiración Automática: Un temporizador basado en el claim exp del JWT detecta el vencimiento del token (300 s), destruye el almacenamiento y redirige al operador a la pantalla de ingreso sin fugas de memoria.
Defensa de Rutas y Navegación Adaptativa: El guard funcional rolGuard intercepta accesos indebidos (403 hacia /sin-acceso) y anónimos (401 hacia /ingresar), mientras que Layout proyecta un menú exclusivo según el rol autenticado.

4. Implementación Técnica en Código Fuente (Angular 19 Standalone)
A continuación se detallan los componentes e interceptores diseñados para cumplir con los requerimientos de la sesión:
4.1. Servicio de Sesión Reactivo con Angular Signals (sesion.service.ts)
SesionService centraliza el almacenamiento en sessionStorage, decodifica el payload JWT en memoria (soporta tanto roles planos como realm_access.roles emitidos por Keycloak) y programa el cierre automático al llegar a exp.
export type RolSitra = 'MINERO' | 'G2_ACOPIADOR' | 'G1_MAYORISTA';@Injectable({ providedIn: 'root' })export class SesionService {  private readonly router = inject(Router);  private readonly tokenActual = signal(this.tokenGuardado());  private temporizadorExpiracion: ReturnType<typeof setTimeout> | null = null;  readonly rol = computed<RolSitra | undefined>(() => {    const payload = this.leerPayload();    if (!payload) return undefined;    const lista = [...(payload.roles ?? []), ...(payload.realm_access?.roles ?? [])];    if (lista.some((r) => r === 'G1_MAYORISTA' || r === 'Mayorista')) return 'G1_MAYORISTA';    if (lista.some((r) => r === 'G2_ACOPIADOR' || r === 'acopiador')) return 'G2_ACOPIADOR';    if (lista.some((r) => r === 'MINERO' || r === 'Minero')) return 'MINERO';    return undefined;  });  readonly documento = computed(() => this.leerPayload()?.documentoIdentidad ?? this.leerPayload()?.sub ?? '');  readonly nombreUsuario = computed(() => this.leerPayload()?.preferred_username ?? this.leerPayload()?.name ?? this.documento());  readonly autenticado = computed(() => !!this.tokenActual() && !this.tokenVencido());  guardar(token: string): void {    sessionStorage.setItem('sitraoro.accessToken', token);    this.tokenActual.set(token);    this.programarExpiracion();  }  cerrar(): void {    this.cancelarTemporizador();    sessionStorage.removeItem('sitraoro.accessToken');    this.tokenActual.set(null);    void this.router.navigateByUrl('/');  }  private programarExpiracion(): void {    this.cancelarTemporizador();    if (!this.tokenActual()) return;    const exp = this.leerPayload()?.exp;    const restante = exp ? exp * 1000 - Date.now() : 0;    if (restante <= 0) { this.expirar(); return; }    this.temporizadorExpiracion = setTimeout(() => this.expirar(), Math.min(restante, 2_147_483_647));  }}
4.2. Guard Funcional de Control de Acceso RBAC (rol.guard.ts)
Implementado mediante la moderna API funcional CanActivateFn de Angular. Valida si la sesión está activa y si el rol del usuario satisface la lista de roles autorizados en data['roles']. Resuelve bifurcación limpia: 403 (/sin-acceso) o 401 (/ingresar).
import { inject } from '@angular/core';import { CanActivateFn, Router } from '@angular/router';import { RolSitra, SesionService } from './sesion.service';export const rolGuard: CanActivateFn = (route) => {  const sesion = inject(SesionService);  const router = inject(Router);  const roles = route.data['roles'] as RolSitra[];  if (sesion.puedeEntrar(roles)) return true;  return router.createUrlTree([sesion.autenticado() ? '/sin-acceso' : '/ingresar']);};
4.3. Interceptor HTTP Funcional con Bypass OIDC (trace-id.interceptor.ts)
Inyecta Authorization: Bearer <token> en cada petición a la API. Detecta y excluye peticiones a Keycloak para prevenir bloqueos por cabeceras CORS en preflight (OPTIONS), y captura respuestas 401 para provocar logout automático.
export const traceIdInterceptor: HttpInterceptorFn = (request, next) => {  if (request.url.includes('/protocol/openid-connect') || request.url.includes(':38081')) {    return next(request);  }  const sesion = inject(SesionService);  const token = typeof sessionStorage === 'undefined' ? null : sessionStorage.getItem('sitraoro.accessToken');  const headers: Record<string, string> = { 'X-Trace-ID': crypto.randomUUID() };  if (token) headers['Authorization'] = `Bearer ${token}`;  return next(request.clone({ setHeaders: headers })).pipe(    catchError((error: unknown) => {      if (token && typeof error === 'object' && error !== null && 'status' in error && error.status === 401) {        sesion.expirar();      }      return throwError(() => error);    })  );};
5. Análisis y Reflexión Técnica: Seguridad en Aplicaciones de Página Única (SPA)
1. Almacenamiento del Token: sessionStorage vs localStorage vs HttpOnly Cookies:
sessionStorage (Estrategia elegida en SITRA-ORO): Almacena el JWT durante el ciclo de vida de la pestaña del navegador. Evita que scripts maliciosos en otras pestañas lean el token y asegura que, al cerrar la ventana, las credenciales no persistan en disco.
Riesgo mitigado frente a localStorage: localStorage persiste indefinidamente hasta que se limpie manualmente. En terminales compartidas de centros de acopio minero, un operador que olvide cerrar sesión dejaría sus credenciales expuestas permanentemente.
Cookies HttpOnly y CSRF: Las cookies HttpOnly bloquean la lectura de JavaScript contra XSS, pero requieren protección estricta contra falsificación de peticiones en sitios cruzados (CSRF) y complican la integración con Authorization Servers externos en dominios independientes.
2. El Guard de Frontend no reemplaza la Seguridad del Backend (Defensa en Profundidad):
Un error crítico en desarrollo web es asumir que un Guard en Angular garantiza la seguridad del sistema. El código del frontend corre íntegramente en el cliente y puede ser manipulado mediante DevTools o peticiones cURL directas. Por consiguiente, el guard rolGuard cumple una función de Experiencia de Usuario (UX) guiando la navegación, mientras que la autorización estricta e inviolable recae en el Resource Server de Spring Boot mediante la validación de firma criptográfica RS256, emisor verificado y comprobación de GrantedAuthority con hasRole('G1_MAYORISTA').
6. Hallazgo Técnico Resuelto Durante la Implementación
Incidencia Detectada:
Al intentar iniciar sesión desde la SPA en http://localhost:4200/ingresar, la consola del navegador reportaba un fallo inmediato de CORS (Status 0 / Preflight Failure) impidiendo la obtención del token en Keycloak.
Causa Raíz:
El interceptor global traceIdInterceptor agregaba la cabecera personalizada 'X-Trace-ID' a todas las peticiones salientes. En el intercambio CORS Preflight (OPTIONS), Keycloak devolvió 'Access-Control-Allow-Headers' permitiendo únicamente cabeceras estándar (Authorization, Content-Type, etc.) y rechazando X-Trace-ID.
Solución Implementada:
Se refinó traceIdInterceptor para omitir peticiones dirigidas al protocolo OIDC de Keycloak (puerto 38081). Asimismo, se configuró en cuenta-minero.ts la equivalencia transparente de DNI a username (75848157 -> mayorista.demo1), logrando un flujo de login 100% fluido y seguro.
